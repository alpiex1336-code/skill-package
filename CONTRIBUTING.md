# Contributing

Contributions should preserve the package contract: `SKILL.md` is authoritative, companion files provide depth on demand, and edits must not create duplicate rules or hidden contradictions.

## Change process

1. Read `SKILL.md` (**NON-NEGOTIABLE EXECUTION GATES** and **Read order** first) and the companion files touched by your proposal.
2. For non-trivial changes, run the package's Recursive self-application workflow: **PRE-FLIGHT**, meta-orchestra with runtime subagents when Task is available, integration by `theme_key`, Work Filter, edit, verify, and stop on saturation signals.
3. Keep Slot A, Slot B, and Slot C entries in `reference-word-banks.md` under the correct headings.
4. Update `CHANGELOG.md` for behavior-affecting contract edits; tag releases for material contract changes (see README **Versioning**).
5. Do not add secrets, private URLs, proprietary long-form text, or unlicensed third-party content.

## Pull request checklist

- The change has a clear `theme_key` or issue summary.
- `SKILL.md` and companion references do not contradict each other.
- Verification performed is stated honestly.
- New vendor/product names are illustrative, useful, and not endorsements.
